## 6. UML diagrams

### 6.1 Class diagram: domain model (database schema)

```mermaid
classDiagram
    direction LR
    class User {
      +int id
      +str name
      +str email «unique»
      +str avatar_color
    }
    class Meeting {
      +int id
      +int owner_id
      +str title
      +datetime started_at
      +int duration_ms
      +str platform
      +str language
      +str media_url
      +str source_filename
      +int source_size_bytes
      +participants() Participant[]
      +host() Participant
    }
    class Participant {
      +int id
      +str name
      +str email «unique, nullable»
      +str color
    }
    class MeetingParticipant {
      +str role  «host | attendee»
    }
    class Channel {
      +int id
      +str name
      +bool is_private
      +str description
    }
    class TranscriptSegment {
      +int id
      +int position
      +int start_ms
      +int end_ms
      +str text
    }
    class Summary {
      +str overview
      +list~str~ keywords
      +list~Note~ notes
      +str generated_by
    }
    class Chapter {
      +str title
      +str description
      +int start_ms
      +int end_ms
    }
    class ActionItem {
      +str text
      +bool is_completed
      +date due_date
      +int timestamp_ms
      +str source «ai | user»
    }
    class Comment {
      +str body
    }
    class Bookmark {
      +datetime created_at
    }
    class Soundbite {
      +str title
      +int start_ms
      +int end_ms
    }
    class ChatMessage {
      +str role
      +str content
      +list citations
    }
    class TopicTracker {
      +str name
      +list~str~ keywords
    }

    User "1" --> "*" Meeting : owns
    User "1" --> "*" Channel : owns
    User "1" --> "*" TopicTracker : owns
    Meeting "1" *-- "*" MeetingParticipant
    MeetingParticipant "*" --> "1" Participant
    Meeting "*" -- "*" Channel : meeting_channels
    Meeting "1" *-- "*" TranscriptSegment
    TranscriptSegment "*" --> "0..1" Participant : speaker
    Meeting "1" *-- "0..1" Summary
    Meeting "1" *-- "*" Chapter
    Meeting "1" *-- "*" ActionItem
    ActionItem "*" --> "0..1" Participant : assignee
    ActionItem "*" --> "0..1" TranscriptSegment : mentioned at
    TranscriptSegment "1" *-- "*" Comment
    TranscriptSegment "1" *-- "*" Bookmark
    Meeting "1" *-- "*" Soundbite
    Meeting "1" *-- "*" ChatMessage
```

Composition (◆) means the child is deleted with the meeting (`ON DELETE CASCADE`). Plain associations to `Participant`
use `ON DELETE SET NULL`, so removing a person never deletes their tasks or transcript lines.

### 6.2 Sequence diagram: uploading a transcript (create → parse → AI → persist)

```mermaid
sequenceDiagram
    actor U as User
    participant UI as CreateMeetingModal (Next.js)
    participant API as FastAPI /api/meetings/upload
    participant P as transcript_parser
    participant S as services.meetings
    participant AI as services.ai (Claude or Gemini ▸ fallback heuristic)
    participant DB as SQLite (+FTS5 triggers)

    U->>UI: drop standup.vtt, pick channels, Upload
    UI->>API: multipart/form-data (file, title, channel_ids…)
    API->>API: size ≤ 5 MB, UTF-8 check
    API->>P: parse_transcript(content, "auto", filename)
    P-->>API: [ParsedSegment(speaker, text, start_ms, end_ms)]
    API->>S: create_meeting(user, MeetingCreate, segments, source file)
    S->>DB: INSERT meeting, participants (dedupe by email/name), channels
    S->>DB: INSERT transcript_segments
    Note over DB: AFTER INSERT trigger indexes text into segments_fts
    S->>AI: summarize(MeetingContext)
    alt LLM key set (ANTHROPIC_API_KEY or GEMINI_API_KEY)
        AI->>AI: provider.parse(…, schema=_Summary) — Claude SDK or Gemini REST
        AI-->>AI: on error/refusal/quota → HeuristicSummarizer
    else no key
        AI->>AI: HeuristicSummarizer (keywords, chapters, action items)
    end
    AI-->>S: SummaryDraft
    S->>DB: UPSERT summary, chapters, AI action items (keep user/completed)
    S->>DB: COMMIT

```

### 6.3 Sequence diagram: transcript ↔ player synchronization (frontend)

```mermaid
sequenceDiagram
    actor U as User
    participant T as TranscriptPanel
    participant PC as PlayerContext (virtual clock)
    participant PB as PlayerBar / SeekBar
    participant R as requestAnimationFrame

    U->>T: click line "Sarah Chen · 00:47"
    T->>PC: seek(47000, {play: true})
    PC->>PC: clock.ms = 47000, playing = true
    loop every animation frame while playing
        R->>PC: tick(now)
        PC->>PC: ms += Δt × rate → setCurrentMs
        PC-->>PB: currentMs (progress + time label)
        PC-->>T: currentMs
        T->>T: activeSegmentIndex(starts, ms) via binary search
        T->>T: highlight active line, scroll into view (if following)
    end
    U->>PB: drag seek bar to 50 %
    PB->>PC: seek(durationMs × 0.5)
    PC-->>T: new currentMs → new active line scrolled into view
    U->>T: scroll manually while playing
    T->>T: follow = false → show "Sync with audio"
```

## 9. Five-minute demo script (for the evaluator)

1. **Home** (`/`): greeting, assistant cards, Recent / AI Feed. Press **Ctrl+K** and search "SSO" to jump to the exact transcript moment.
2. **Meetings**: use Filters → Participants, try *Hosted by me*, open a channel, hover a card for **Details** and ⋯, then bulk-select and move.
3. Open **Q4 Product Roadmap Planning**: press ▶, click transcript lines, drag the seek bar, and use **Find** "SSO".
4. Open **Smart Search** → Questions / Sentiment / Talk time / Topic Trackers.
5. Action items: add, assign, complete. Then **Refine Summary**, Edit, and Export (MD / TXT / PDF).
6. Ask **AskFred** "What decisions were made?" and click a citation.
7. **Capture ▾ → Paste transcript → Use a sample** to create a meeting; rename it and delete it.
8. Visit **Tasks** (My / All), **AskFred** (across meetings), **Analytics**, and **Settings** → Appearance → Dark.

## 10. Known limitations

- No real audio or speech-to-text (out of scope); playback is simulated so the sync behaviour is fully demonstrable.
- The built-in AI engine is extractive (it selects real transcript sentences); set `GEMINI_API_KEY` or `ANTHROPIC_API_KEY` for abstractive LLM summaries.
- Single user by design; data isolation already filters by `owner_id`, so multi-user only needs real auth in `current_user`.
- SQLite on free hosting tiers resets on redeploy; the demo re-seeds automatically.
